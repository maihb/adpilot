# adpilot MVP 设计文档

> 2026-08-19 · 状态：设计中，未开工
>
> **本文档是范围与决策的真相源。** 代码落地后，凡「会随代码变的事实」（表结构、接口清单、env 名、依赖版本）一律不在这里抄第二份，只留指针 + 为什么这么设计。

## 一、这是什么

**跨平台广告投放数据中台**——把 Meta / TikTok Ads 的投放数据拉进来、算成能看的指标、用 LLM 生成人话日报和异常诊断，客户在小程序上自助查看。

**开源自用工具，不是 SaaS。** 每个使用者部署自己的实例、填自己的 API 凭据、连自己的账户，数据不出自己的服务器。

### 双重目标，优先级不能倒

| | 目标 | 含义 |
|---|---|---|
| 主 | **可验证的工程作品** | 别人 clone 下来 `docker compose up` 就能跑起来看到东西；分层、测试、CI 经得起翻 |
| 次 | 替掉作者代运营工作里的手工活 | 作者是 0 号用户，真实场景驱动需求，避免闭门造车 |

**主次颠倒的后果**：为了自己好用而堆特化逻辑 → 别人跑不起来 → 作为作品价值归零。所以凡是「只有我需要」的东西一律走配置或插件，不写死进主干。

## 二、要解决的真实问题

这些不是想象出来的需求，是作者在代运营工作里实际每天踩的：

### 1. 每天手工搬数字

平台后台导出 → 拼表 → 算 CPA/ROAS → 写日报 → 发客户。一个客户 15 分钟，三个客户就是一小时，而且**搬错数字比不发日报更糟**。

### 2. 余额预充模式下，余额归零 = 广告直接停

TikTok Ads 的预充模式原文：`Your ad spend will be automatically deducted from your available cash balance`。**不是降速，是停**。停一次冷启动学习期就白跑了（3–5 天），重开又要 3–5 天。

**这是个纯规则问题，不需要 AI**：按近 N 天日均消耗算余额可撑天数，低于阈值就告警。**MVP 第一个真正有用的功能就是它。**

### 3. 库存跟不上投放速度

电商投放的隐藏杀手：广告刚跑起来，主推款断货，学习期作废。**库存数据在店铺后台、投放数据在广告后台，两边没人对**。

### 4. 平台报表和客户后台永远对不上

归因窗口、浏览归因、跨设备、两个平台各自邀功——**报表相加大于实际订单数是正常现象**。处理方式是两个数字都列出来 + 固定附差异说明，而不是想办法让它们一致。

### 5. 平台字段会漂移

Meta 一年能改三次字段叫法，TikTok 同理。**上个月的报表用的什么口径，三个月后要能查得到。**

### 为什么是双库（面试必被问，理由要站得住）

| | PostgreSQL | MongoDB |
|---|---|---|
| 存什么 | 客户、账户、**归一化后的日指标**、日报、结算 | 平台 API / 导出文件的**原始快照** |
| 为什么 | 金额要 `numeric` 和事务，指标要 JOIN 和聚合 | **字段随平台版本漂移**，且原始数据要能回溯审计 |
| 可变性 | 可更新 | **append-only，写入后永不修改** |

**边界原则：钱和关系走 PG，未经解释的原始事实走 Mongo。** 归一化是一次单向转换（Celery 任务），失败可以拿 Mongo 里的原始快照重跑——这是双库的核心价值，不是为了用而用。

**反例（不这么做）**：把广告指标直接塞 Mongo 图省事。对账要事务、报表要 JOIN，最后会在应用层手写一遍关系数据库，得不偿失。

## 四、技术选型

每一项都要能回答「为什么是它」，不能答「因为流行」：

| 层 | 选型 | 为什么 |
|---|---|---|
| 语言 | Python 3.12 + **uv** | uv 装依赖比 pip/poetry 快一个量级，`uv.lock` 锁定可复现；3.12 是 FastAPI 生态最稳的版本 |
| Web | **FastAPI** | 拉广告 API 是大量 IO 等待，async 是对的模型；自带 OpenAPI → 前端类型可生成（延续 gots 的接口契约主张） |
| ORM | SQLAlchemy 2.0 + Alembic | 2.0 的 typed ORM 有真实类型提示；Alembic 做迁移版本化。候选对比与使用边界见 [Schema 与迁移方案](2026-08-19-schema-migration.md) |
| 任务 | **Celery + RabbitMQ** | 拉数是长任务、平台有速率限制、失败要退避重试——正是 MQ 的活。选 RabbitMQ 不选 Redis broker：需要真正的 ack 和死信队列，任务丢了等于数据缺一天 |
| 关系库 | PostgreSQL 18 | `numeric` 精确金额、窗口函数算环比、JSONB 存半结构化维度 |
| 文档库 | **MongoDB** | 见上节 |
| 缓存 | Redis | 平台 API 令牌桶限流 + 热点指标缓存 |
| 客户端 | **uni-app 3 + Vue 3 + TS + Pinia** | 一套代码出微信小程序 / H5 / App。客户是小商家，**小程序扫码就能看，不装 App 不注册账号**是刚需 |
| 后台 | Vue 3 + TS + Element Plus | 内部操作台，密度优先 |
| LLM | 供应商适配器（Claude / OpenAI / Gemini） | 同一个 `LLMProvider` 接口，换供应商零改动业务代码 |
| 质量 | ruff + mypy + pytest + GitHub Actions | CI 绿灯是给读代码的人看的第一个信号 |

### 数据接入：MVP 不接 Ads API

**理由是工程判断不是偷懒**：Meta / TikTok 的开发者应用审核能拖掉一周以上，而作者手上真实客户的广告账户此刻还没开始跑量——**没有真实数据可拉，接了 API 也是空的**。

所以 MVP 走 `CsvImportProvider`（后台导出的 CSV），这正是作者现在手工做的事，替掉它立刻产生价值。API 适配器留好接口，凭据到位当天可插上：

```python
class ReportProvider(Protocol):
    name: str

    def parse(self, content: bytes) -> ParseResult: ...
```

> **签名在落地时改过一次**（2026-08-20，D3）。原稿是 `fetch(account, day)`，那是
> **拉取型**的形状；而文件导入是**推送型**——日期是从文件内容里读出来的，不是入参，
> 一份文件也通常横跨多天多对象。硬塞进同一个签名，结果是两边各带一半用不上的参数。
>
> 接平台 API 适配器时的做法：在这个 Protocol 上加一个 `fetch` 方法，两种形态各有
> 各的入口。**要统一的是产物（`RawRows`）而不是入口**——产物一致，归一化、重跑、
> 审计才是同一套代码。真相源是 `src/adpilot/providers/base.py`。

**这是作者做过的模式**（多模型图像生成的 `ImageGenerator` 适配器注册表），迁移过来是同一套思路：新增供应商只实现接口，调用方零改动。

## 五、AI 层：三件事，边界写死

### 做什么

| 能力 | 输入 | 为什么值得用 LLM |
|---|---|---|
| **日报撰写** | 当日指标 + 环比 + 已执行的操作记录 | 日报的价值不在数字，在**那一行人话**（「成本上升是周末 CPM 普涨，未做调整，观察到周一」）。数字表格代码能生成，人话不能 |
| **异常诊断** | 规则引擎筛出的异动 + 该账户历史 | 「CPA 涨了 40%」是规则算的，「大概率是素材疲劳，频次已到 3.2，建议换素材而不是降价」是 LLM 给的 |
| **知识库问答（RAG）** | 使用者自己导入的投放 SOP | 新人问「不跑量怎么办」，答案来自你自己的 SOP 而不是通用废话 |

### 🔴 三条硬边界（这部分是设计主张，比功能重要）

1. **LLM 不碰钱。** 改预算、开关广告、调出价一律**只产出建议，不自动执行**。理由：LLM 会自信地犯错，而广告花的是真金白银，且错误不可逆（学习期重置）。所有执行动作必须人工确认。

2. **能用规则算的绝不用 LLM。** 余额可撑天数、库存断货预警、指标环比阈值——全是确定性计算，写成可单元测试的规则。**LLM 只负责解释和表达，不负责判断和计算。** 这条不只是省钱，是让系统的关键路径可测试。

3. **LLM 输出必须过 schema 校验。** 走 structured output，Pydantic model 校验失败即重试，绝不把裸文本直接写进数据库或发给客户。

**每次 LLM 调用记录 token 数与预估成本**——延续作者已有的调用日志与成本追踪实践。

## 六、数据模型（骨架，以 Alembic 迁移为准）

> 下面只是骨架。表定义的真相源是 `src/adpilot/models/`，schema 怎么演进见
> [Schema 与迁移方案](2026-08-19-schema-migration.md)。

PostgreSQL 核心表：

- `clients` — 客户
- `ad_accounts` — 广告账户（平台、币种、时区、所属客户）
- `daily_metrics` — 归一化日指标（账户/广告系列/广告组维度，唯一键 `(account_id, level, object_id, stat_date)`）
- `balances` — 账户余额快照（余额告警的依据）
- `products` — 商品与库存快照（断货预警的依据）
- `reports` — 生成的日报/周报（含 LLM 产出与人工修订两版）
- `actions` — 操作记录（改了什么预算、换了什么素材——**日报要能说清「做了什么」**）
- `llm_calls` — LLM 调用日志与成本

MongoDB 集合：

- `raw_reports` — 原始报表快照，`{provider, account_id, stat_date, fetched_at, payload}`，append-only

### 时区：一个必须在建模阶段就定死的坑

广告账户时区、店铺时区、客户所在时区**可以是三个不同的值**（作者手上真实案例：店铺 Los Angeles、广告账户 Anchorage，日切点差 1 小时）。

**约定**：`stat_date` 一律存**广告账户时区下的自然日**，并在 `ad_accounts` 上记录时区。**日报必须注明口径。** 不注明的话，客户拿他自己后台的数字来对，永远差一截。

## 八、🔴 开源边界：什么绝不进仓库

**从第一个 commit 起按公开仓库纪律写。** 「先放私有仓库以后清理」是陷阱——git 历史会把密钥一起带走，清理要重写全部 commit hash。

| 进仓库 | 不进仓库 |
|---|---|
| 代码、schema、迁移、Docker、CI、文档 | `.env`（Ads API token、LLM key、DB 密码） |
| `.env.example`（只有键名和说明） | 真实客户数据（本来就在数据库不在 git） |
| **脱敏的示例数据 + seed 脚本** | 具体客户的账户 ID、BM ID、结算价、联系人 |
| RAG 导入器代码 | RAG 语料（运行时导入，使用者自己喂） |

**本设计文档也遵守这条**：上文所有真实场景（余额预充、时区差、库存断货）都是脱敏后的通用描述，不含任何客户身份信息。

## 十、开放项的决定

判断标准统一是「**陌生人 clone 下来最容易跑起来**」——这是主目标（可验证的工程作品）的直接推论。

### 1. 仓库：GitHub public，从第一个 commit 起

`git@github.com:maihb/adpilot.git`，**开仓即公开**（原计划 private 到 D14 再转，实际直接公开了）。自建 GitLab 只做 `--mirror` 备份，**不作主仓库**——commit 历史本身是作品的一部分，一次性 squash 上传观感等于「抄的」。

**公开是既成事实，所以第八节的开源纪律没有缓冲期**：密钥、真实客户名、广告账户 ID 从第一个 commit 起就不能进仓库。git 历史会留住删掉的东西，事后清理要重写每一个 commit hash。

### 2. LLM：默认走 OpenAI 兼容协议，不绑定任何一家

```
LLM_BASE_URL / LLM_API_KEY / LLM_MODEL
```

**不默认 Claude 也不默认 Gemini**——开源使用者未必有这两家的凭据，而 OpenAI 兼容协议是当下事实标准（DeepSeek、Kimi、通义、本地 Ollama、vLLM 全都兼容），改三个环境变量就能换。Claude / Gemini 各写一个原生适配器放在 `providers/` 下作为示例，同时也是「适配器注册表」这个设计的活证明。

### 3. 客户端登录：扫码 + 短期 HMAC token

**不用微信授权登录**——那需要企业小程序资质和备案，开源使用者大多没有，H5 端也用不了。扫码方案：内部后台给客户生成一次性链接/二维码 → 客户端换取短期 token → 到期自动失效。

作者在自建基础设施里已经把部署脚本的静态密码改造成过区域绑定的短期 HMAC token，同一套思路复用。

### 4. 投放操作记录：MVP 手动登记，必填

日报里「本期做了什么」这段是交付价值所在（动作要可数），**数据来源只能是操作记录**。不填就只能靠回忆，回忆必然漏。

MVP 做成手动登记且**发布日报前校验非空**；API 接通后升级为自动抓取平台变更日志，手动登记降级为补充。**先手动不是妥协**——自动抓取拿不到「为什么这么调」，那才是日报里唯一有价值的部分。
