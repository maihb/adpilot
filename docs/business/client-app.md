# 客户端界面

**代码**：`client/src/pages/`（四屏）· `client/src/utils/`（口径怎么显示）·
`client/src/api/request.ts`（唯一请求出口）· `tests/test_client_source.py`（形状门禁）

**范围出处**：[客户端设计](../design/2026-08-21-client-app.md) · 里程碑 D10–D11

**OpenAPI tag**：无。它是 [`portal`](portal.md) 那组接口的消费方，自己不提供接口。

## 一句话职责

**把客户该知道的三件事，在一分钟内说清楚**：昨天花了多少、余额还能撑几天、有没有
什么事要他知道。

**不负责**：任何写操作（客户端全只读）、任何判断（那是 `rules/`）、任何解释
（那是 LLM 层，还没做）。

## 四屏

| 屏 | 用哪个接口 | 这屏存在的理由 |
|---|---|---|
| 扫码 / 输码 | `redeemInvite` | 唯一入口。H5 靠链接带码，小程序多一个扫一扫 |
| 看板（首页） | `getPortalProfile` + `listPortalAccounts` + 每账户 `getPortalRunway` | 「我有哪些号、哪个号快没钱了」 |
| 账户明细 | `listPortalMetrics` | 每日时间线，默认近 14 天 |
| 告警 | `listPortalAlerts` | 默认只给未解决的 |
| 我的 | 无 | 口径说明 + 退出。**不是凑数的**：时区、归因差异、数据更新时机这三句话得有个地方放 |

**首页是账户列表而不是一块合并大看板**，因为客户名下的账户**币种和时区可以各不
相同**（示例数据里就有三种币种、三个时区）。合并要先决定汇率，而汇率是个全新的
数据域。一账户一卡片，是让「不能相加」在结构上说出来。

## 🔴 显示口径：四条「显示错了不会报错」的规则

这四条是**业务规则不是实现细节** —— 它们决定客户看到的是什么意思。

| 规则 | 一句话 |
|---|---|
| **`null` 不是 0** | 金额和比率下发的永远是**字符串**，而 JS 里 `Number(null) === 0`。可撑天数为 `null` 是「近期没花钱，算不出来」，显示成 0 天就是说「明天停投」 |
| **可撑天数是三态** | 没录过余额 → 「余额未录入」；有余额但近期没消耗 → 「近期无消耗」；能算 → 数字 + 按 `is_alerting` 上色。前两态**灰色，不告警** |
| **缺数据的那天不补零** | 后端不返回没有数据的那天。明细页把区间补全后，那天显示「未导入」，**不显示 0** —— 「花了 0」和「没导入」是两件事 |
| **币种和时区必须挨着数字** | 日期是**账户时区**下的自然日，不做本地时区转换（它是标签不是时刻）。金额带币种前缀 |

配套的文案约定：无定义一律显示 `—`（不是空白，空白看起来像还没加载完）；日均
消耗的回看窗口里缺了几天要写出来（「按 X 至 Y 内 N 天有数据的日均算」），不写的话
客户会拿一个被低估的日均去做充值决定。

## 能读文档就够的部分

| 规则 | 一句话 |
|---|---|
| 默认区间 | 明细页近 14 天。覆盖「上周同一天」那个异动基线，客户看到告警时两天都在眼前 |
| 告警默认范围 | 只给未解决的，可切换到全部历史 |
| 停投账户 | 首页照常列出（带「已停投」标签）。**藏起来只会让客户来问人** |
| 退出登录 | 只删本机那份票。**服务端没有对应动作** —— 自签票撤销不了，那张票在到期前仍然有效，这句话写在「我的」页上 |
| 票的续期 | 冷启动时剩余不足 2 天就静默续一次；收到 401 续一次并重放，**一次启动只准续一次** |
| 邀请码进过地址栏 | 换到票之后立刻从 URL 上抹掉（`history.replaceState`），别留在浏览器历史和截图里 |
| 二维码里放什么 | **H5 链接，不是小程序码** —— 小程序码要 AppID 和已发布的小程序，开源使用者大多没有 |

## ⛔ 必须读源码的部分

- **数字转换只许发生在 `client/src/utils/` 里。** `pages/` 和 `stores/` 里出现
  `Number(` / `parseFloat(` / `parseInt(` 会被 `tests/test_client_source.py` 拦下。
  那条门禁挡的正是上面第一条规则 —— 一个 `Number()` 就能把「算不出来」变成
  「还能撑 0 天」，而它不会报错。加页面前先读 `utils/decimal.ts` 的模块注释。

- **告警类型的中文名是后端枚举的第二份拷贝**（`pages/alerts/alerts.vue` 的
  `KIND_NAMES`）。页面对认不出的 kind 做了回落，所以对不上时**不会报错**，只会
  把英文标识显示给客户。有一条测试双向盯着它和 `models/alert.py` 的 `AlertKind`。

- **区间合计是前端用 JS 的 number 算的，不是 Decimal**（`utils/aggregate.ts`）。
  那是**显示用的合计，不是对账口径** —— 要拿去对账的数字必须来自后端。

## 已知残余

- **没有图表**。小程序没有 DOM，图表库要走 canvas 适配层，两端渲染差异是时间黑洞。
  明细页用的是「一天一行 + 一根横条」，信息量足够回答那三个问题。
- **微信小程序端只验到编译通过**，运行时没验 —— 那要装微信开发者工具并注册 AppID。
  H5 是默认演示路径，理由与「不做微信授权登录」同源。
- **没有推送**。客户只能自己打开看（模板消息要企业资质，见 [portal.md](portal.md)）。
- **还没有日报那一屏。** 后端在了（D14：`listPortalReports` / `getPortalReport`，
  只返回已发布的），客户端界面还没做 —— 它是这四屏之后最该补的一屏，因为日报
  才是客户真正等着看的东西。显示时注意口径那四条规则同样适用：金额是字符串、
  对照期三项可能同时为 `null`（那时环比整段不显示，**不要拿 0 当基线**）。
- **一次只能看一个账户的时间线**，多账户合并要先解决汇率。
