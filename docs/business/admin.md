# 内部操作台

**代码**：`admin/src/pages/`（五屏）· `admin/src/api/request.ts`（唯一请求出口）·
`admin/src/utils/format.ts`（口径怎么显示）· `tests/test_frontend_source.py`（形状门禁）

**范围出处**：[内部后台设计](../design/2026-08-21-admin-console.md) · 里程碑 D12

**OpenAPI tag**：无。它消费的是内部那八组接口，自己不提供接口。

## 一句话职责

**运营的操作台**：把每天的手工活（导数据、看告警、发码）搬到一个页面上。

**不负责**：任何判断（在 `rules/`）、任何解释（那是 [LLM 层](llm.md)）—— 日报里
那段人话由模型起草，运营在这里**改完才发得出去**，见 [日报](reports.md)。

## 六屏，按运营真实的一天排

| 屏 | 什么时候用 | 主要接口 |
|---|---|---|
| **导入**（首页） | 每天，最高频 | `importReportFile` → `getTaskStatus` |
| **告警** | 每天，第二高频 | `listAlerts` · `sweepAlerts` |
| **日报** | 每天，出完告警之后 | `generateReport` · `reviseReport` · `publishReport` |
| 客户列表 / 新建 | 新客户上手时 | `listClients` · `createClient` |
| 客户详情 | 发邀请码、停用客户 | `listInvites` · `createInvite` · `revokeInvite` · `updateClient` |
| 账户明细 | 核对数字、录余额、重跑归一化 | `listDailyMetrics` · `recordBalance` · `normalizeAccount` |

**首页就是导入**，没有仪表盘。做一个「今日概览」很好看，但它回答的问题（哪个账户
花超了）告警页已经在回答，而且回答得更准 —— 两个地方说同一件事，早晚有一天会说得
不一样。

## 🔴 写操作按「能不能收回来」分三级

滥用二次确认等于没有确认：每个操作都弹窗，人就会条件反射地点「确定」。

| 级别 | 例子 | 怎么做 |
|---|---|---|
| 可逆 | 建客户、录余额、重跑归一化 | 直接做 |
| 难逆 | 导入一份报表 | 直接做，但**导完必须显示导进去了什么** —— `raw_reports` append-only，导错了删不掉，只能靠归一化重跑盖过去 |
| **不可逆 / 立刻影响外部人** | **停用客户**、**作废邀请码**、**发布日报** | 二次确认，且确认文案里写出后果 |

**停用客户是全系统唯一一个「点下去立刻影响外部人」的操作。**
`require_client_scope` 每次请求都查一遍 `is_active`，所以那个客户手上还没过期的票
**当场失效**（不用等 7 天）。确认文案必须说这句话，不能只写「确定停用吗」。

**发布日报同样收不回来**：客户端立刻就能看到，而且那份日报从此不能改、也不能重新
生成 —— 客户手上那份截图不会自己更新，库里和客户手里说的不是一回事比两边都旧更糟。
确认文案要把这两句都写出来。生成和修订则是**可逆**的（重新生成、再改一次），不弹窗。

**作废邀请码管不到已经换出去的 token** —— 自签、自包含，撤销不了，最多再活 7 天。
要立刻断掉某个客户，只能停用客户。这一句也写在确认框里。

## 🔴 邀请码明文只出现一次

`createInvite` 的返回值里那个 `code` 是明文码**唯一**出现的地方，列表接口只有状态
（库里存的是哈希，还原不回来）。这对界面是硬约束：

- 生成之后**不是 toast**，是一个留在页面上的框，带复制按钮，直到运营主动关掉；
- 关掉前说清楚「关掉就再也看不到了」；
- 列表里那些历史码**不显示码**，只显示状态 —— 页面上要写明这不是坏了。

## 导入在界面上是两段

后端刻意做成一半同步一半异步，界面必须跟着分开：

| 段 | 同步性 | 界面要做的 |
|---|---|---|
| 解析 + 落快照 | **同步**，在请求里 | 失败时**原样显示后端说了什么** —— 认不出日期列时它会列出实际表头，那正是运营要拿去改导出设置的信息 |
| 归一化 | 异步，Celery | 显示任务状态。`task_id` **可能是 `null`**（队列连不上，快照照样落好），这时给一个手动触发入口，不是永远转圈的进度条 |

只显示一个「导入成功」，运营会以为数字已经能查了 —— 而归一化可能还在队列里、也可能
失败了。

⚠️ 上传上限 **10 MiB**，界面在**选文件时就拦**：传完十兆再说不行，那十兆是白传的。

## 能读文档就够的部分

| 规则 | 一句话 |
|---|---|
| 票的有效期 | **8 小时，不滑动续期**。后台权限比客户端大得多 |
| 票过期时 | **不跳转**，就地弹登录框；登录后 **只重放 GET** |
| 为什么不重放写操作 | 导入不是幂等的（`raw_reports` append-only）。让人重点一次的成本是一次点击，而一次悄悄的重复导入没人会发现 |
| 并发 401 | 只弹一次登录框。首屏会同时发好几个请求，弹三个框比丢数据更糟 |
| 没有删除 | 客户、账户、指标都没有删除接口，后台也不提供 —— 停用能解决所有真实需求，删除会让历史数据变成孤儿 |
| 没有批量操作 | 在「几个客户」的规模下省不下多少时间，却把每个操作的后果放大 N 倍 |
| 余额的币种 | 取账户的，**界面不让选** —— 让人手填早晚会出现「账户是 USD、余额录成 CNY」的一条快照，而算出来的可撑天数看起来完全正常 |

### 🔴 错误消息一律原样显示后端那句话

收口在 `api/request.ts` 的 `reason()`，全站一份。后端**刻意把 `detail` 写成能指导
操作的**：认不出日期列时列出表头（运营拿去改导出设置）、日报发不出去时说清缺的是
哪一件（没人审过 / 没有操作记录，两件的补救动作不一样）。换成一句「操作失败」等于
让人去猜，或者来问人。

⚠️ 别只判 `NeedsRedo` —— 那个类型只表示「票过期了、已经重新登录、请再点一次」，
业务错误抛的是 `ApiError`。只判前者会把后端那句话安静地吞掉，而错误分支恰恰是最少
被走到、最晚被发现的地方（**这个 bug 在日报屏上跑出来过一次**）。

## ⛔ 必须读源码的部分

- **数字转换只许发生在 `admin/src/utils/` 里。** 页面里出现 `Number(` 会被
  `tests/test_frontend_source.py` 拦下 —— 理由和客户端一字不差：后端下发的金额是
  字符串，而 `Number(null) === 0` 会把「算不出来」显示成 0。

- **网络调用只许出现在 `api/request.ts`。** 同一条门禁扫的：认证头、401 之后的
  重新登录都在那一个文件里，绕过去的请求不带票，也不会走重新登录那条路。

- **告警类型的中文名是后端枚举的第二份拷贝**（客户端还有第三份）。有测试双向盯着
  它和 `models/alert.py` 的 `AlertKind`。

## 已知残余

- **日报屏一次只看一个账户。** 没有「今天哪些日报还没发」的跨账户待办视图 ——
  后端的列表接口是按账户的。账户是个位数时切换成本不高，真到了十几个再说。
- **没有网络层隔离**。后台不该暴露在公网，但 MVP 不做 nginx 规则 / IP 白名单 /
  VPN —— 那是部署形态的事。**它唯一的防线是运营的账号密码 + 8 小时的票**，这句话
  也写在 README 里。
- **没有新建广告账户的界面**。`createAdAccount` 接口在，但一个客户的账户是一次性
  配置，用 curl 或 Swagger 建更快，为它做一屏是范围蔓延。
- **没有图表**（同客户端）。
